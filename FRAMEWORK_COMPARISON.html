2 Key Conceptual Differences

Six dimensions that most affect day-to-day E/E architecture work.

Specialized vs. General

Domain semantics
  • Yours: natively knows ECUs, pin roles (IN/OUT/SUPPLY/GND), interfaces (CAN/LIN/PWM/ANALOG/SENT/FlexRay), harnesses, safety classes.
  • Others: domain-agnostic — you re-create those semantics via profiles / stereotypes.

Auto-mapping vs. Manual

Pin allocation
  • Yours: engine auto-assigns signals to physical pins by interface, role, electrical need, safety class.
  • Others: allocation is a manual modeling activity (allocation matrices / allocate relations).

Verification

Rule engine
  • Yours: 21 fixed rules + R1–R6 sizing, compiled C, deterministic PASS/WARN/FAIL.
  • Others: configurable checks, but you author each one (Model Advisor / constraints).

Data & Versioning

Git-ability
  • Yours: JSON + C + git → clean diffs, merges, PRs, CI.
  • System Composer: .slx binary — hard to diff/merge.
  • SysML v2: textual syntax is git-friendly (its headline win).

Standardization

Interoperability
  • SysML v2: OMG standard + REST API + portable interchange across tools.
  • System Composer: partial / vendor formats.
  • Yours: custom schema — full control, weaker ecosystem exchange.

Documentation

Deliverables
  • Yours: 44 generators auto-produce bus diagrams, signal dictionaries, IO matrices, DFDs, harness/wiring books from data — no manual editing.
  • Others: report generation exists but needs setup / licensed add-ons.

7 When Each Fits

EE Architect Design
Choose when speed, zero license cost, git/CI-native flow, automatic pin allocation, and turnkey E/E documentation matter most — accepting a custom schema and in-house maintenance.
System Composer
Choose when you need behavioral simulation, mature Polarion / requirements round-trip, and vendor support — accepting license cost, binary models, and building the E/E solver logic yourself.
SysML v2
Choose when standardization, tool portability, multi-domain scope, and long-term interoperability outweigh a higher training investment and the lack of built-in E/E automation.
One-liner: your framework is a vertical, opinionated E/E solver + doc generator that already delivers domain automation (mapping + documentation) which would take significant custom effort and licensing to reproduce in System Composer — while System Composer and SysML v2 are horizontal, general-purpose modeling platforms that model anything but solve or document nothing domain-specific out of the box.
